# 异构专家库 v2 交叉验证设计

## 目的

GSM8K capacity v2 已通过全部冻结门槛，但它使用宽度 512 的残差头，旧五专家使用宽度
256。v2 专家库允许每个专家按自身冻结结构加载，检验新增数学专家和两个新任务族是否
扩大安全 oracle 的可用空间。该步骤不训练路由。

## 固定专家与任务族

- 旧五专家：QASC、SNLI、PAWS-Wiki、CLINC、TruthfulQA，权重与 v1 专家库一致。
- 新专家：GSM8K capacity v2 种子 42，宽度 512；它在新同族验证上通过所有门槛。
- 路由元数据共九个来源：原六来源、TruthfulQA、HellaSwag、GSM8K。
- HellaSwag 专家因未通过门槛而不加入，但其已消费训练/验证行可用于观察其他专家的
  跨族行为。
- 所有缓存来自同一冻结 2B 父模型、相同 2048 维候选表示与父决策头。

## 预注册完整性与安全门槛

1. 六个专家必须覆盖九个验证来源；每个权重、数据文件和缓存 manifest 哈希匹配。
2. 完整分布安全 oracle 保持父模型正确性，且逐行交叉熵、Brier、上下文优势不退化，
   proper loss 必须严格改善才可选择专家。
3. oracle 逐行违规为 0；每个来源的准确率和交叉熵均不得退化。

所有九个来源都已用于开发，结果只用于判断路由 headroom，不支持发布阶段的零样本声明。
