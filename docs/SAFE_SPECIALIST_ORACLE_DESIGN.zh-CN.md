# 约束优先的安全专家 oracle 设计

## 原理解构

上一版把 NLL、Brier 和上下文优势加权成一个标量，再选择成本最低的专家。标量可以补偿：
少数样本上的上下文奖励或 Brier 改善，可能掩盖 NLL 恶化或父模型正确答案被破坏。这个问题
不是换权重就能彻底解决，因为任何有限权重都允许一个目标补偿另一个目标。

本方案把 RLCD 式偏好构造拆成两步：

1. **可行性过滤**：先判断专家是否满足逐行安全约束；
2. **安全集合内排序**：只在可行专家中按 proper-loss 改善排序。

父路径始终是可行默认项。没有专家通过约束或只出现并列时，选择父路径。

## 逐行硬约束

对每个固定专家和每个带金标的离线样本，只有同时满足以下条件才允许进入候选集合：

1. 如果父模型 top-1 正确，专家 top-1 也必须正确；
2. 专家金标 NLL 不得高于父模型；
3. 专家 Brier 不得高于父模型；
4. 专家金标的 full-minus-null 对数概率优势不得低于父模型。

在安全集合中，以 `NLL + 0.5 × Brier` 的改善最大者为目标专家。改善必须严格大于 0；
同值按固定专家名排序，但父路径在零改善时优先。

这些约束使用金标，只能生成离线路由监督或测量 oracle，不能直接用于线上推理。它们的作用是
定义“允许路由学习模仿什么”，而不是给线上路由器额外输入。

## 固定输入

- 与交叉矩阵完全相同的 724 个已消费验证行。
- 专家库固定为 QASC 端点以及 SNLI、PAWS-Wiki、CLINC 的种子 42 端点。
- 冻结父模型、特征缓存、专家权重和候选顺序。
- 不调阈值，不读取来源作为专家输入，来源只用于离线分组审计。

## 通过门槛

1. 父模型正确决策破坏数为 0；
2. 被选路径逐行 NLL、Brier 和上下文优势退化数均为 0；
3. 每个任务族的准确率和 NLL 均不退化；
4. 合并准确率至少提高 `1` 个百分点；
5. 合并 NLL 至少下降 `0.02`；
6. 合并平均 proper-loss 改善至少 `0.02`。

通过后，后续多专家路由的训练标签必须来自同一约束优先规则；标量加权 oracle 只保留为对照。
