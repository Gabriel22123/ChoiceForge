# QASC 语义路由残差机制筛选设计

## 目的

上一轮“冻结父模型 + 全局残差头”证明父参数可以逐张量保持不变，但组合后的函数仍会在旧任务上漂移。原因是同一个残差对每个请求都生效；参数没变不等于旧任务输出没变。

本轮只检验一个机制假设：**能否根据请求本身的冻结语义表示，稀疏地启用新增专家，同时让旧任务尽量沿用父函数。** 所有评测任务均已消费，本轮不能产生发布或泛化结论。

## 组合函数

对请求中的候选表示 \(h_1,\ldots,h_n\)，先计算不依赖候选顺序的请求表示：

\[
r=\frac{1}{n}\sum_i h_i
\]

路由器给出一个请求级门值，残差头给每个候选一个修正：

\[
g=\sigma(\operatorname{Router}(r)),\qquad
z_i=z_i^{parent}+g\,\operatorname{Residual}(h_i)
\]

残差最后一层以全零初始化。因此训练前无论门值是多少，组合输出都与父模型逐值相同。路由器只读取冻结父模型产生的语义向量；推理时不读取数据来源、任务族、样本 ID、答案或训练标签。

## 与 RLCD 思路的关系

这里采用 RLCD 的核心思想：把“在新信号上获得收益”和“不要破坏已有行为”写成同一个可审计的学习问题，而不是训练后再凭整体准确率判断。具体约束为：

1. 新任务行用公开 gold label 学习候选残差；
2. 旧任务回放行同时保持父模型在完整上下文和空上下文上的概率分布；
3. 完整上下文相对空上下文需要保留正向材料优势；
4. 旧任务回放行对门值施加稀疏惩罚，使“不启用新专家”成为默认偏好；
5. 路由器仍只能从语义中学习何时启用，训练元数据不进入推理输入。

这不是照搬某个实现。关键改动是把保持约束作用在**组合函数**和**请求级路由**上，直接针对上一轮已观察到的失败模式。

## 数据边界

- 训练：512 条公开旧任务回放 + 512 条公开 QASC；QASC 权重为 0.5。
- 已见评测：训练语料中预先存在的 test/validation 切分。
- 消费开发集：384 条 BIG-bench 与 128 条 QASC。
- 特征：冻结父模型对完整请求及去材料请求的最终候选向量。
- 特征、训练权重和私有逐行输出只保存在 Git 忽略目录。
- 只使用公开数据、公开链接和公开模型。

## 预注册训练设置

- 随机种子：1701。
- 一轮、1,024 行、batch 2、累积 4，共 128 次更新。
- 残差宽度：256；路由宽度：128；dropout：0。
- 初始门值：0.25。
- AdamW 学习率：3e-4；weight decay：0.01；梯度裁剪：1.0。
- gold 目标：交叉熵 + 0.5 Brier。
- 完整父分布 KL：1.0；空上下文父分布 KL：1.0。
- 材料优势损失：0.25，目标间隔 0.05。
- 旧任务门稀疏惩罚：0.02。

训练顺序与每行候选排列在训练前由种子固定，并写入本地计划文件。

## 进入下一阶段的条件

必须全部满足：

- 初始组合 logits 与父模型完全一致；
- QASC 训练门均值至少比旧任务回放高 0.05；
- 已见准确率相对父模型不低于 -0.005，NLL 不高于 +0.01；
- 消费开发集准确率不低于 -0.005；
- 消费开发集每个来源的材料优势不低于父模型 -0.005；
- QASC validation 准确率至少提高 0.03，NLL 至少降低 0.02；
- QASC 材料优势至少提高 0.02。

通过只允许进入“实时模型集成 + 输出契约审计”。随后仍需新公开任务族、多个随机种子、许可证审计和完整发布审查，才能形成开源候选。

## 仍待验证的风险

- 冻结特征筛选不等于实时推理实现；需要验证候选换序、ID 重命名、保存重载和严格 JSON 输出。
- 单个标量门可能不足以表达多个新能力之间的路由关系。
- 路由器可能只学到 QASC 的表面文体，而非可迁移的“需要组合证据”结构；必须用新的公开任务族检验。
