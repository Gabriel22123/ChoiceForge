# 候选编码：从学习换序稳定到结构上的独立评分

首轮实验中，三种训练目标都只有 4/24 条检查样本做到所有候选顺序均正确。
因此本轮先研究表示结构，使用相同 CE 目标比较两种候选编码。

## 两种方式

### 联合编码：`candidate_encoding=joint`

```text
任务 + 材料 + 候选 A + 候选 B + 候选 C
                    ↓ 同一个双向编码器
                 sA, sB, sC → softmax
```

各候选可以读到其他候选，但其表示也可能随列表位置、上下文距离和相邻描述改变。
所有候选共享同一个评分头，并不能自动消除这些影响。

### 独立评分：`candidate_encoding=independent`

```text
任务 + 材料 + 候选 A → 同一个编码器和评分头 → sA
任务 + 材料 + 候选 B → 同一个编码器和评分头 → sB
任务 + 材料 + 候选 C → 同一个编码器和评分头 → sC
                                           ↓
                                   softmax(sA,sB,sC)
```

这里的“独立”指输入中只有当前候选，模型参数完全共享。
定义 `s_i=fθ(task,context,description_i)` 后，调换列表顺序只会调换分数的排列。
这一性质来自结构，不是宣称模型已经学会了更强的推理能力，也不是一种新的架构理论。

当前实现训练时最多将 8 个候选序列组成一个编码批次；推理时每次编码一个候选，
确保同一候选不会因为其他候选改变批次填充长度。softmax 仍会有小量浮点归约误差。
完全相同分数时，接口保留首次出现的候选作为 argmax，因此硬决策的平局行为仍可能随顺序改变。

## 控制什么、不控制什么

两组都重新初始化适配器和评分头，并核对初始化哈希，避免模型起点不同。
使用相同样本、候选换序计划、CE 目标、两份训练视图、优化器、学习率与更新次数。
两组都先检查完整请求的 token 预算，避免独立评分悄悄获得更多可训练样本。

这不意味着相同计算预算。独立评分重复处理任务和材料，会改变编码序列数量、批次形状、
dropout 抽样和执行时间。本轮记录实际前向输入数量与 token 槽位，同时单独测量已加载模型的请求延迟。

## 必须同时看的结果

1. **换序稳定性**：每个候选的概率变化、最终答案是否一致。
2. **语义正确性**：各任务正确率、所有检查顺序是否均答对。
3. **概率质量**：原始和验证集温度缩放后的 NLL、Brier、ECE 与覆盖率。
4. **计算成本**：训练时间、实际编码输入量、按候选数量分组的推理延迟。

## 能力取舍

独立评分看不到其他候选的内容。候选描述应能独立理解：例如“创建日历提醒”
具有独立含义，而“以上都不是”“同时满足 A 和 B”需要结合其他选项解释。
因此独立评分不一定适合所有候选定义，也可能损失跨候选比较能力。

另一个直接结果是：对固定任务、材料和候选描述，加入第三个候选不会改变原来
两个候选的分数差。温度为 T 时，`p(A)/p(B)=exp((sA-sB)/T)`，与其他候选无关。
这有利于固定语义的排序，却不能表达必须结合整个候选集合才能发生的偏好变化。
候选概率仍会因为 softmax 分母变化而改变；复制一个同义候选也会分走概率质量。
因此不能把“某候选在这组选择中有 90% 概率”直接解释为“它在开放世界中有 90%
概率正确”。校准需要匹配候选生成方式、候选数量和困难负例分布。

我们没有通过预先给候选排序、重复运行多种顺序后投票，或缓存答案来制造稳定结果。
这些工程方法可以单独研究，但不属于本轮的结构对照。

## 使用

`configs/eurobert-independent-pilot.json` 提供独立评分配置。
旧配置默认使用联合编码，旧权重仍按其原始模式加载。
两种方式的参数形状虽然一致，训练输入含义已经变化，因此常规 `--init-from`
禁止跨模式加载；本轮均从公开原始底座重新训练。

本轮仍只有一个随机种子、384 条训练样本，测试集已用于开发诊断。
换序稳定性改善即使成立，也不能证明通用零样本能力。
