# 多专家交叉效用矩阵设计

## 要回答的问题

QASC、SNLI、PAWS-Wiki 与 CLINC 已分别形成正效用专家。下一步不能直接训练路由，必须先
知道每个专家在所有任务族上的真实成本：它是只在本任务有效、能安全迁移，还是会伤害其他
任务？交叉矩阵也给出“知道每行真实标签时，父模型 + 专家库最多能改善多少”的 oracle
上界，避免在没有可用信号时继续调路由。

## 固定输入

- 冻结父模型与既有候选特征缓存不变。
- 专家库：QASC、SNLI、PAWS-Wiki、CLINC。
- QASC 使用已冻结二元路由实验中的残差专家；其他三个来源保留种子 42/43/44 全部结果。
- 交叉矩阵覆盖固定验证拆分：QASC 128、SNLI 96、PAWS-Wiki 96、CLINC 42、
  Typed Decisions 320、JSON Schema 42，共 724 行。
- 专家输入不包含来源名、任务族、样本 ID 或标签；来源只用于离线分组汇总。
- 反事实成本继续使用 NLL、`0.5 × Brier` 与 `0.25 × context-margin`，margin 为
  `0.05`。

## 两类结果

1. **全种子矩阵**：对 SNLI、PAWS-Wiki、CLINC 的三个种子分别计算每个验证任务族的
   平均带符号效用、准确率差、NLL 差和应打开率。QASC 报告其固定单端点。
2. **固定专家库 oracle**：不根据本次结果挑种子，预先指定每个来源的种子 42，QASC 使用
   固定端点。对每行比较父路径和四个完整专家路径的反事实成本；最小成本路径构成 oracle。

oracle 只用于测量可分离上界，不能在真实推理中使用，因为它读取金标成本。其选择记录不写入
发布证据，只保留来源级汇总。

## 冻结判定

该矩阵进入多专家路由设计需同时满足：

1. 四个专家在各自任务族上的固定端点平均效用至少 `+0.01`；
2. oracle 合并平均效用至少 `+0.03`；
3. oracle 相对父模型准确率至少提高 `1` 个百分点；
4. oracle NLL 至少下降 `0.02`；
5. 至少一个专家在至少一个非本任务族上的平均效用为负，证明保留父路径和学习选择机制确有
   必要，而不是把某个专家全局打开即可。

通过后只允许进入新的多专家路由协议设计。后续路由仍必须做留一任务族验证，不能使用本矩阵
的验证标签调阈值。
