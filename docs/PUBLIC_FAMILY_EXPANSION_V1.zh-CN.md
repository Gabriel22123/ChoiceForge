# 公开任务族扩展协议 v1

## 为什么现在扩任务族

现有七个任务族已经用于专家训练、路由校准或失败诊断，继续在这些验证集上改阈值会把
开发反馈误当成零样本泛化。上一轮独立专家模块恢复了 6.43% 的覆盖率，但安全精度只有
47.62%，说明当前主要限制是跨任务校准样本不足。

本阶段先增加任务机制的跨度，再训练路由。数据角色在读取标签前固定：

| 数据 | 机制 | 本阶段角色 | 是否可用于方法选择 |
|---|---|---|---|
| HellaSwag | 情境续写与常识一致性 | 专家训练 + 已消费验证 | 是 |
| GSM8K | 多步数值推理与答案核验 | 专家训练 + 已消费验证 | 是 |
| SciFact | 科学主张与证据关系 | 最终封存任务族 | 否；只在协议与权重固定后运行一次 |

## 数据与许可证边界

- HellaSwag 使用 `Rowan/hellaswag` 固定版本
  `218ec52e09a7e7462a5400043bb9a69a41d06b76`，官方仓库为 MIT。
- GSM8K 使用 `openai/gsm8k` 固定版本
  `740312add88f781978c0658806c59bc2815b9866`，官方仓库为 MIT。
- SciFact 固定官方仓库提交 `68b98a56d93e0f9da0d2aab4e6c3294699a0f72e`；官方
  许可证将 claims/evidence 标注置于 CC BY 4.0，abstract corpus 置于 ODC-By 1.0，
  代码置于 Apache-2.0。官方压缩包已只为固定字节数与 SHA-256 下载到忽略目录，保持
  未解压状态；当前未读取封存标签或样本文本。
- 原始及转换文本都留在 Git 忽略目录。可发布仓库只包含下载器、固定版本、文件哈希、
  转换代码、许可证归属和聚合证据。

## 防泄漏规则

1. HellaSwag 分别从官方 train 与 validation 拆出 512/256 行；选择键只含 activity、
   context、无角色候选文本和 source ID，不含 label。
2. GSM8K 从官方 train 按 question-only 哈希拆出 512/256 行，剩余 6,705 行不用；
   solution rationale 不进入模型输入。
3. GSM8K 的正确数值只在入选后用于监督与确定性困难负例构造；候选位置由
   question + candidate 文本哈希决定。
4. 两个验证集在首次专家实验后都标记为已消费，不进入最终发布声明。
5. SciFact 在训练方法、路由结构、阈值规则、随机种子和权重哈希全部冻结后才物化；
   失败后不得用同一批结果调参并再次宣称盲测。

## 本阶段顺序

1. 验证转换器、文件哈希、无答案拆分和候选位置分布；
2. 缓存冻结 MiniCPM5-2B 父模型表示；
3. 为 HellaSwag、GSM8K 分别训练三个随机种子的独立残差专家；
4. 只有专家在各自已消费验证集上达到预注册的效用、准确率和 NLL 门槛，才加入专家库；
5. 用扩展后的训练任务族重做跨族路由校准，冻结最终协议；
6. 最后一次性打开 SciFact，报告完整失败或成功，不追改阈值。

该阶段仍是本地研究，不配置 GitHub 远端，不上传代码、数据或权重。
