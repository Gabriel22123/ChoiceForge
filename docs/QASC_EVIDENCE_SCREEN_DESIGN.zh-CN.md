# QASC 八候选证据组合筛选：冻结设计

## 问题

前两轮分别修复了 BoolQ 的全选 Yes 偏置、学会了项目生成的证据翻转格式，但都没有稳定改善自然任务的上下文使用。本轮检验更具体的问题：在保留旧函数的同时，加入真实的八候选科学问答，能否让模型同时学会读取两条证据、比较候选语义，并避免退化成固定标签偏好。

## 数据边界

- 仅使用 QASC 官方 train 与 validation。官方仓库明确按 CC BY 发布，固定的 Hugging Face 转换版本为 `a34ba204eb9a33b919c10cc08f4f1c8dae5ec070`，本地逐文件校验 SHA-256。
- 每题保留 `question`、`fact1`、`fact2` 和全部八个答案文本；不使用常直接复述答案的 `combinedfact`。
- 原始 A–H 字母不进入模型。候选按 `SHA-256(question, candidate text)` 重排，再分配不会进入模型的 `option-01` 至 `option-08` ID。
- 训练集从官方 train 中选 512 条，重排后八个正确位置各 64 条；验证集从官方 validation 中选 128 条，各 16 条。每个位置内部按不含答案的内容哈希选择，并先通过 768 token 的输入门禁。
- 原始及转换文本都留在 Git 忽略目录；可发布部分只有转换代码、文件指纹、归属说明和聚合指标。
- BIG-bench 文件带有明确的训练 canary，本轮不用；Super-NaturalInstructions 汇编任务的上游许可不统一，本轮也不用。

## 训练

- 起点：`functional-retention-screen-v1/warm-functional-context`。
- 512 条旧任务回放继续使用父端点原始概率做函数蒸馏；512 条 QASC 使用公开金标。
- 一轮、每次有效 batch 8、128 次更新；LoRA 范围不变。
- 为降低前两轮出现的旧任务 NLL 退化，encoder/head 学习率降为 `2.5e-6 / 2.5e-5`。
- 上下文优势损失保持 `weight=0.25, gap=0.05`。

## 事先固定的晋级条件

全部条件同时通过才进入多随机种子复核：

1. 已见准确率相对父端点不低于 -0.5 个百分点，NLL 增量不超过 0.01；相对 release control 的每来源准确率不低于 -2 个百分点。
2. 已消费开发集准确率相对父端点不低于 -0.5 个百分点；每来源相对 control 不低于 -2 个百分点；三种来源的上下文优势均为正。
3. QASC validation 准确率相对父端点至少提高 3 个百分点，且绝对值至少 18%；原始 NLL 至少下降 0.02。
4. QASC 的平均金标上下文优势为正，且相对父端点至少提高 0.02。

QASC validation 在本轮结果生成后即永久成为已消费开发集。即使晋级，也不能据此形成发布结论；最终发布仍需要从未读取的新任务族和多随机种子结果。
