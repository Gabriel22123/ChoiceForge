# Encoder / Decoder 公平比较设计

状态：两个固定底座、训练入口、验收器和盲测原始文件已准备；正式六端点比较尚未启动，
ARC 选择仍未启封。

## 问题

在相同的任务、上下文和候选项接口下，约 2B 规模的双向 encoder 与因果 decoder，
谁更适合做不生成文本的通用零样本决策？比较对象是：

- encoder：`EuroBERT/EuroBERT-2.1B`，固定 revision
  `81245a4d71f43452badf5e04458e4ddb831ff109`；
- decoder：`openbmb/MiniCPM5-2B-Base`，固定 revision
  `96a57cd572a02506b4500f54427dca24970c1bac`。

MiniCPM5 的官方模型元数据声明 Apache-2.0，固定版本包含 2,516,756,480 个 BF16
参数；本项目只下载并校验原始底座，不把底座权重打进发布包。

## 共享决策接口

两条路线都不调用文本生成，也不解析模型自由输出的 JSON。每个候选项单独与同一份
任务和上下文编码，经过共享标量头得到一个分数；所有候选分数做 softmax，程序再构造
固定 JSON。这样比较的是表示和适配能力，而不是 decoder 是否服从输出格式。

decoder 没有 `[MASK]`。它的每条序列按以下顺序编码，并读取最后一个非 padding token
的隐藏状态：

```text
Task: ...
Context (data): ...
Candidate: ...
Decision score:
```

encoder 也必须使用独立候选编码。它继续读取放在候选描述前的 `[MASK]` 表示。两者看见
相同的任务、上下文和候选语义，但读出位置符合各自注意力方向；候选 ID 不进入模型。

## 必须匹配的条件

1. 相同公开训练行、官方划分、每步任务比例、候选排列和随机种子。
2. 主比较使用相同 LoRA rank、最后 32 层适配范围、共享头宽度、损失函数、一次曝光
   和更新数。EuroBERT 共 32 层，MiniCPM5 共 42 层；这里匹配实际适配层数，并报告
   精确可训练参数，而不把“都覆盖全部层”误称为同等预算。只有主比较冻结后，才可把
   decoder 全 42 层作为单列敏感性实验。
   在不加载权重的结构审计中，主配置的可训练参数分别为 EuroBERT
   `11,015,169`、MiniCPM5 `10,097,153`，相差约 8.3%；正式运行会再次从实际参数表核算。
3. 每步实例数相同；同时单独报告实际 token、注意力 token-pair、耗时、在固定训练
   检查点采样到的设备内存和可训练参数。MPS 没有可靠的进程级峰值统计接口，因此不把
   离散采样值写成精确峰值。参数规模接近不代表计算量相等。
4. 验证集只拟合各自温度；测试集不做选择、调参或早停。
5. 先运行小规模可学习性和内存 smoke；两条路线都通过后才冻结正式三种子协议。

冻结数据已用 MiniCPM5 tokenizer 预检：1,888 个请求共形成 7,517 条 admission/候选
序列，最长 218 tokens、P95 为 127，没有任何序列超过 768-token 上限。正式训练仍会
再次执行 `require_all_rows` 检查，任何一条丢失都会令端点失败。

## 主终点

- 已训练任务：PAWS、SNLI 的 accuracy、NLL、Brier；
- 未训练任务：在任何结果可见前冻结的 ARC-Easy 与 ARC-Challenge 子集；
- 候选换序：所有测试顺序保持率和全顺序正确率；
- 选择性判断：置信度阈值下的覆盖率、准确率和人工复核率；
- 工程代价：训练/推理延迟、固定检查点的设备内存采样、token 与 attention token-pair。

decoder 只有同时满足以下预注册条件才可成为默认路线：PAWS+SNLI 的种子内平均准确率
至少两次获胜；任何种子/主任务不下降超过 1 个百分点；六个主任务比较的平均 NLL 不变
差；Bandit、CLINC、GoEmotions、JSON Schema 的平均准确率和平均 NLL 均不变差；所有
decoder 换序审计完全稳定；封存 ARC 的种子内平均准确率至少两次获胜，且六个 ARC
比较的平均准确率不变差。

ARC 数据源固定为官方 `allenai/ai2_arc` 版本，并按其数据卡记录的 CC BY-SA 4.0
处理。正式盲测前必须保存 revision、文件哈希、确定性选择规则和完整 protocol；ARC
不得进入训练、温度校准或端点选择。

## 解释边界

- 这是两个具体公开底座与相同决策头的比较，不能外推为所有 encoder 对所有 decoder。
- 两个底座的预训练语料、tokenizer 和原始能力不同；结果是端到端路线比较，不是纯粹
  的注意力方向消融。
- 公共 benchmark 可能出现在预训练语料中。冻结测试防止本项目调参泄漏，但不能排除
  底座预训练污染。
- 只有三种子收益方向稳定、配对区间和工程成本都报告后，才决定默认路线。
